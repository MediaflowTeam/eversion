# Tests

The `test/` directory contains EVersion's GoogleTest test executables and its
CMake script tests.

## Test Targets

| CTest name | Source | What it checks |
| --- | --- | --- |
| `Version.*`, `VersionDeclare.*`, `ComponentInfo.*` | `eversion_test`: `version_test.cc`, `version_declare_test.cc`, `component_info_test.cc` | The version types, parsing, the header generated by `eversion_declare()` for the `eversion_test_consumer` target, and the component metadata ABI. |
| `PluginInfo.*` | `eversion_plugin_info_test`: `plugin_info_test.cc` | Loads the `eversion_test_plugin` module, generated by `eversion_declare_plugin()`, with `dlopen` and validates its metadata. |
| `CMakeContract.Declare` | `cmake/declare_contracts.cmake` | Configures small projects that call `eversion_declare()` and expects invalid or duplicate arguments to fail, and `NO_INSTALL` to add no install paths. |
| `CMakeContract.InstallGeneratedHeaderChain` | `cmake/install_generated_header_chain.cmake` | Installs EVersion from the build tree, builds and installs `cmake/install_producer`, which installs a generated header, and builds and runs `cmake/install_final_consumer` against both installed packages. |

The CMake script tests run `cmake` in subdirectories of
`build/<preset>/cmake_contracts/`, with the generator, the make program, and the C++
compiler of the enclosing build; `CMakeContract.InstallGeneratedHeaderChain` checks
that its sub-projects use them. That test also needs a build tree with install
rules, which a top-level build has by default.

## GoogleTest Contract

Tests use GoogleTest through CMake package config mode:

```cmake
find_package(GTest CONFIG ...)
include(GoogleTest)
```

`test/CMakeLists.txt` uses `QUIET` followed by an immediate
`message(FATAL_ERROR ...)`, which gives a clearer installation diagnostic than
the default CMake error message.

The build does not download GoogleTest. If CMake cannot find `GTest CONFIG`,
install GoogleTest with your package manager or build it yourself, then pass the
package location through `CMAKE_PREFIX_PATH` or `GTest_DIR`.

## Test Target Rules

- Link every GoogleTest executable to `GTest::gtest_main`.
- Register GoogleTest binaries with `gtest_discover_tests(<target>)`.
- Do not call `add_test(NAME ... COMMAND ...)` directly for GoogleTest binaries.
- Use `.cc` for test sources.
- Name cases `TEST(Suite, Case)` so CTest produces clear, unique names.
- Pass build-time-known inputs through `target_compile_definitions()` instead of
  per-test command-line arguments, so discovery works without custom argv.

When the same source is built into more than one test executable, register the
extra build with a unique suffix:

```cmake
gtest_discover_tests(example_test TEST_SUFFIX .variant)
```

For `-fno-exceptions` variants, also set:

```cmake
target_compile_definitions(example_test PRIVATE GTEST_HAS_EXCEPTIONS=0)
```

## Running Tests

Run the standard quality gate:

```sh
python3 scripts/quality.py check
```

Run only the build and CTest phase:

```sh
python3 scripts/quality.py test
```

Useful manual CMake commands:

```sh
cmake --preset quality
cmake --build --preset quality
ctest --preset quality
```

Run the tests under AddressSanitizer and UndefinedBehaviorSanitizer with the
`asan-ubsan` preset:

```sh
cmake --preset asan-ubsan
cmake --build --preset asan-ubsan
ctest --preset asan-ubsan
```
